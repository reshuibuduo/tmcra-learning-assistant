# 架构与数据边界

## 三条独立链路

1. **采集与存储**：浏览器 AudioWorklet 输出 24 kHz、单声道 PCM16；先提交 IndexedDB，再上传。`tmcra.audio.v2` 每个二进制消息由 8 字节大端偏移加 PCM 组成。服务端拒绝间隙和冲突，重叠字节一致时去重，`fsync` 后发送累计 ACK。
2. **识别**：服务器读取持久 PCM，转 16 kHz 后发送豆包语音。确认字幕进度保存在字节检查点中；失败重试未确认尾段。空闲和长会话会结束/轮换单个 ASR 连接，不等于结束录音。
3. **理解与展示**：定稿字幕进入短滚动窗口；并行触发翻译、概念解释和显式启用的记忆关联。划线提问独立流式输出。引用校验失败的结果不作为有依据的记忆提示展示。

## 有界状态与真实状态

- `capture.state` 区分持续收到音频、停滞、连接断开和已停止；不只依赖 `session.status=recording`。
- `asr.microphone.state` 与采集状态独立；`byte_offset` 和 `epoch` 标记识别检查点和连接轮次。
- 本地 `next` 是已缓存字节，`acked` 是服务器确认字节，`intent` 标记用户是否手动停止。
- 页面刷新不调用麦克风 API，也不替用户新建录音。新建和继续都来自明确的按钮操作。
- 录音期间持续重连只恢复传输。服务重启后会话显示 interrupted，等待手动继续。

## 数据去向

- 浏览器：未确认的 PCM 缓存、学习背景、短期工作区访问令牌。
- 自托管服务：PCM、字幕、解释、问答及审计元数据，位于 `runtime/state/`。
- 豆包语音：用户主动采集或上传的音频。
- 选定推理服务：完成翻译/解释/问答所需的字幕窗口、问题和学习背景；不是默认发送原始 PCM。
- TMCRA：默认关闭；开启后按配置进行转写写入、学习资料导入和检索。

当前设计是单用户工作区，不包含组织级权限隔离、计费、配额或多租户密钥管理。语音聚类不等于声纹身份识别。关闭标签页或系统休眠时，没有后台原生录音守护进程替用户继续录音。

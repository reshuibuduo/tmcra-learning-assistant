# 验收说明

## 可重复的离线测试

- 后端：协议、鉴权、窗口合并、引用校验、字幕翻译、流式提问、手动录音结束、偏移续传、ASR 恢复。
- JavaScript：PCM 转换、UI 绑定、字幕选择、流式解析、上传确认丢失与重连、手动结束后拒绝新音频。
- 初始化：缺失凭证、文件权限、重复初始化保留数据、环境配置不执行 shell、密钥不打印。
- 启动烟测：在随机本机端口启动独立服务，验证一次性登录、未授权拒绝、合成文本会话及手动结束；不接入麦克风、不访问付费 API。
- macOS：20 项悬浮窗状态模型测试和源码构建。界面验收与状态模型测试分开。

实际测试数量和通过状态以当前 GitHub Actions 及命令输出为准，不把历史数字当作当前验收结果。

## 已完成过的真实上传实验

2026-11-08 使用短合成语音完成浏览器→上传服务→豆包 ASR 实验：故意丢弃一次 ACK、断开连接并刷新页面，855300 字节音频最终补传，输入和服务端文件 SHA256 一致，产生最终转写。实验使用独立测试库，没有使用真实会议内容。

这是一个短样本的功能验证，**不是**长会议稳定性、真实麦克风、多说话人准确率或端到端延迟的总体结论。测试结果也不是“永不丢音”的保证。

## 使用者应补做

1. 手动开始麦克风录音，确认电平、上传确认字节与字幕持续增长。
2. 在可控环境短暂断网，确认缓存增长、重连补传且服务器字节连续。
3. 手动结束，确认麦克风立即释放，待上传归零，再看到服务端收尾完成。
4. 在目标浏览器、目标操作系统和目标网络下测试 30–120 分钟。
5. 多说话人测试分别记录 ASR 文本正确率、匿名分组效果；不把连接内编号当成跨连接身份。
6. 分别测音频→定稿、定稿→翻译/解释、提问→首字，不把不同边界混成一个延迟数字。
